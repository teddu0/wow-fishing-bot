# Инструкции для работы над WoW Fishing

## Контекст проекта

- Общайтесь с пользователем на русском. Подписи GUI и сообщения пользователю — на русском; имена в коде — на английском.
- Целевая среда: Windows 11 x64, русский или английский клиент WoW 3.3.5a, Python 3.12+.
- Разработка возможна на macOS: здесь проверяются GUI, распознавание, OCR, автомат состояний и воспроизведение записей. Реальный захват и ввод проверяются отдельно на Windows.
- Установка, запуск, ограничения распознавания и критерии игровой приёмки описаны в README.md. Сохраняйте его актуальность при изменении поведения.

## Согласованное поведение

- Пользователь сам выбирает окно WoW. Не выбирайте клиент автоматически и не переключайтесь на другой HWND при потере выбранного окна.
- Калибровка полностью автоматическая: без ручного выделения воды, поплавка или области ошибок. Неуверенное распознавание означает отказ от клика; после трёх неудачных пробных забросов — остановку.
- Работа с игрой ограничена изображением экрана и обычным вводом. Чтение памяти, внедрение в процесс, аддоны и фоновый ввод не входят в согласованный подход.
- Сохраняйте проверку идентичности окна, геометрии и фокуса перед вводом. F8 и потеря фокуса прекращают работу независимо от OCR; возобновление только вручную.
- Сообщение о полных сумках останавливает цикл. Живой режим требует OCR выбранного языка клиента (`rus` или `eng`); следующий заброс ждёт проверки после сбора. Язык выбирает пользователь, по умолчанию — русский.
- Replay никогда не отправляет реальный ввод. Отключение OCR допустимо только для проверки записей.
- Подготовка персонажа, удочки, наживки и автосбора остаётся за пользователем. Перемещение, продажа и удаление предметов не входят в текущую версию.

## Границы модулей

- `src/wow_fishing/engine.py` содержит автомат состояний с передаваемым временем. Сохраняйте его независимость от Qt, системных часов и Windows API.
- `vision.py` и `ocr.py` анализируют кадры BGR; `recording.py` и `replay.py` обеспечивают записи и имитацию команд.
- `windows.py` изолирует платформенные адаптеры. Импортируйте Windows-зависимости лениво и сохраняйте платформенные маркеры зависимостей в pyproject.toml.
- `safety.py` отвечает за отмену и защищённый ввод. Освобождение уже нажатых клавиш должно выполняться и при остановке.
- `runtime.py` выполняет фоновую работу, `app.py` обновляет GUI через сигналы/слоты Qt. Не переносите OCR или цикл захвата в поток интерфейса.
- Координаты распознавания — физические пиксели клиентской области; ввод преобразует их в экранные координаты. Учитывайте DPI и отрицательные координаты дополнительных мониторов.
- dxcam закреплён на 0.3.0 из-за использования внутреннего списка DXGI outputs. При обновлении версии проверяйте сопоставление мониторов.

## Проверки изменений

Используйте Python из `.venv`. Для изменений логики запускайте соответствующие тесты; для изменений ввода, OCR и автомата состояний — весь набор. Изменения только документации не требуют запуска тестов.

На macOS/Linux:

```sh
.venv/bin/python -m pytest -q
.venv/bin/ruff check .
QT_QPA_PLATFORM=offscreen .venv/bin/python -m wow_fishing --smoke-test
```

На Windows используйте `.venv\Scripts\python -m pytest -q` и `.venv\Scripts\python -m ruff check .`.

- Если локальные модели находятся в `artifacts/tessdata`, запускайте OCR-тесты с `TESSDATA_PREFIX="$PWD/artifacts/tessdata"`. Для проверки обоих языков нужны `rus.traineddata` и `eng.traineddata`. Наличие этой папки не гарантируется в новой рабочей копии.
- Для тестов используйте `RecordingInput`, искусственные кадры и временные каталоги; не отправляйте ввод в открытые приложения.
- При изменении распознавания проверяйте неоднозначные объекты, фоновые волны, потерю поплавка и реальные записи, если они доступны. Кадры настройки и оценки должны различаться.
- При изменении управления проверяйте однократный клик, остановку, потерю фокуса, устаревшие результаты OCR и отсутствие нового заброса до проверки сумок.
- В отчёте различайте синтетические тесты, OCR на изображениях, воспроизведение видео и проверку в настоящей игре. Пропущенные OCR-тесты не считайте пройденными; число кликов не считайте числом пойманных предметов.
- Цели «18 сборов из 20» и «остановка до 250 мс» нельзя объявлять достигнутыми без измерений на Windows с целевым клиентом.

## Файлы и зависимости

- Не включайте в исходники окружения, кэши, видеозаписи, модели OCR и локальные отчёты из `.venv`, `.bootstrap`, `.python`, `.uv-cache` и `artifacts`.
- Не редактируйте установленные библиотеки и системную установку Python для исправления проекта. Зависимости задаются в pyproject.toml; при их изменении обновляйте uv.lock.
- Данные запуска хранятся вне исходников в каталоге WoWFishing, описанном в README.md. Тесты должны подменять его временным каталогом.
