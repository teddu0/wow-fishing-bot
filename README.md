# Тихая вода · WoW Fishing

Screenshot-бот для русского и английского WoW 3.3.5a на Windows 11. Python 3.12+, dxcam,
OpenCV, NumPy, pywin32, pynput и PySide6. OCR: Tesseract + pytesseract.

**Статус:** первая реализация с автоматическими тестами и воспроизведением видео.
Распознавание эвристическое; точность на настоящем клиенте пока не измерена.
Windows-захват и ввод требуют отдельной проверки на Windows. Наличие тестов
на искусственных кадрах не подтверждает успешность реальной рыбалки.

## Установка и запуск на Windows

Нужны Windows 11 x64, Python 3.12+ x64 и Tesseract с моделью языка клиента:
`rus.traineddata` для русского или `eng.traineddata` для английского.
Установка Tesseract описана в [документации проекта](https://tesseract-ocr.github.io/tessdoc/Installation.html).
Обе модели доступны в [официальном репозитории tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast).
Разместите модель в `tessdata` установленного Tesseract.

Команды установки и запуска выполняйте из корня проекта. Python-пакет
`pytesseract` не устанавливает сам Tesseract и языковые модели.

```powershell
tesseract --list-langs
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -e ".[dev]"
.venv\Scripts\python -m wow_fishing
```

В выводе Tesseract должен быть `rus` или `eng` в соответствии с выбранным языком.
Для английского клиента русская модель не требуется, и наоборот. Отсутствие нужной
модели блокирует запуск; автоматической подмены языка нет.
Если Tesseract отсутствует в `PATH`, укажите
путь к `tesseract.exe` в приложении. Также проверяется стандартное расположение
`C:\Program Files\Tesseract-OCR\tesseract.exe`. F8 зарезервирована для остановки;
клавиша рыбалки — 0–9 или F1–F12, кроме F8, без модификаторов.

1. Подведите персонажа к воде, экипируйте удочку, примените наживку и включите автосбор.
2. Используйте оконный режим или окно без рамки, целиком на одном мониторе.
3. Выберите клиент по заголовку, PID и предпросмотру. Окно не выбирается автоматически.
4. Выберите «Язык клиента»: «Русский» или «Английский» — он должен совпадать с
   языком текста игры. По умолчанию выбран русский. Укажите клавишу рыбалки.
   Для диагностики можно включить запись сеанса.
5. Нажмите «Начать рыбалку», дождитесь проверки OCR и перейдите в выбранное окно
   за пять секунд. Не двигайте камеру и не меняйте масштаб интерфейса.
6. Первые два-три заброса служат автоматической калибровке. Первый пробный заброс
   при найденном кандидате дожидается окончания 35-секундного интервала без клика;
   это нормальное поведение. Если за три пробных заброса калибровка не завершена,
   бот останавливается. После её завершения сбор возможен уже на том же забросе.

Ручного выбора воды, поплавка или области ошибок нет. Бот ищет новый небольшой
объект с красно-оранжевым пером, появившийся после заброса, и сравнивает его между
забросами. Поплавки изменённых моделей и сильно изменённый UI не поддержаны.
Несколько равнозначных кандидатов приводят к отказу от клика. Калибровка требует
сходных образцов в разных местах экрана, чтобы не принять элемент UI за поплавок.

Сумки проверяются по **красному тексту игровых ошибок** во всей клиентской области.
Для русского клиента распознаются «Инвентарь заполнен», «Сумки заполнены»,
«Нет места в сумках»; для английского — «Inventory is full», «Your bags are full»,
«Not enough room in your bags» и близкие варианты из `ocr.py`.
Стандартная английская фраза `ERR_INV_FULL` — «Inventory is full.»
([тексты интерфейса клиента](https://github.com/tekkub/wow-globalstrings/blob/master/GlobalStrings/enUS.lua)).
Первое распознавание полных сумок блокирует заброс и клик; два последовательных
подтверждения останавливают цикл. После клика бот ждёт минимум две секунды и
два результата OCR по кадрам после клика, причём последний кадр должен быть снят
не раньше окончания этой паузы. До этой проверки нового заброса нет.
Если свежего результата OCR нет более восьми секунд, цикл останавливается.
Цвет ошибок должен оставаться стандартным; конкретную формулировку частного сервера нужно
проверить на записи. Это не проверка количества пустых ячеек. Нет сообщения или
его неверно прочитал OCR — нет гарантии обнаружения полных сумок.
Мелкий шрифт и видеосжатие могут приводить к пропуску сообщения: например,
в синтетической записи Tesseract прочитал «Инвентарь» как «Ин вентарь».
Вставленные внутри слова пробелы и произвольные опечатки OCR не исправляются.

## Остановка и второе окно

F8, «Стоп», потеря фокуса, закрытие/сворачивание/перемещение/изменение размера
выбранного окна, ошибка захвата и сбой OCR прекращают цикл. Контроль окна работает
в отдельном потоке с интервалом 20 мс; обработчик F8 не зависит от OCR. Перед
каждым действием повторно проверяются HWND, PID, время создания процесса,
геометрия и фокус. Уже нажатые клавиши освобождаются даже при остановке.
После калибровки три неудачи подряд — поплавок не найден, потерян или поклёвка
не обнаружена за 35 секунд — также останавливают цикл.

Во втором клиенте можно играть **после остановки бота**. Фоновая рыбалка отсутствует:
мышь и клавиатура общие. Проверка фокуса и системная отправка ввода не атомарны;
минимальный промежуток между ними полностью устранить этим способом нельзя.
Задержка остановки до 250 мс — критерий Windows-приёмки, а не измеренная гарантия.
Возобновление всегда вручную, с новой калибровкой. Автонаживка, перемещение,
продажа и удаление предметов не реализуются.

## Разработка и проверка на macOS

GUI, OpenCV, OCR и автомат состояний работают на macOS. Windows-зависимости
устанавливаются только на Windows и импортируются при работе с окнами игры,
предпросмотром и живым сеансом. На macOS выбор окна и запуск рыбалки недоступны.

Если окружение проекта уже установлено, для просмотра GUI достаточно выполнить
из корня проекта:

```sh
.venv/bin/python -m wow_fishing
```

Для первого запуска создайте окружение и установите зависимости:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m wow_fishing
```

В приложении укажите язык клиента в записи и выберите «Открыть запись…» →
«Проверить запись». Для проверки только
распознавания поплавка и цикла отключите «Проверять текст ошибок в записи»:
Tesseract тогда не нужен. Для самого просмотра GUI он также не требуется.
Эта возможность относится только к воспроизведению; живой бот без OCR не запускается.
GUI принимает записи AVI, MP4, MKV и MOV, если их кодек поддерживает установленный
OpenCV. Проверка идёт со скоростью обработки кадров, без ожидания реального времени.
«Стоп» прерывает проверку; F8 в режиме записи действует при фокусе в окне приложения.
Проверка из терминала:

```sh
.venv/bin/wow-fishing-replay screen.avi --without-ocr --report artifacts/replay.json
.venv/bin/wow-fishing-replay screen.avi --tesseract /opt/homebrew/bin/tesseract
.venv/bin/wow-fishing-replay english-screen.avi --game-language eng
.venv/bin/python -m pytest -q
QT_QPA_PLATFORM=offscreen .venv/bin/python -m wow_fishing --smoke-test
.venv/bin/python -m ruff check .
```

CLI использует русский язык по умолчанию; `--game-language eng` выбирает английский,
`--game-language rus` — русский. Выбранный язык записывается в отчёт (`game_language`).
Без `--report` CLI сохраняет `replay-report.json` в текущем каталоге; `--report`
задаёт другой путь. Повторный запуск с тем же путём перезаписывает отчёт.
`--smoke-test` закрывает GUI примерно через 250 мс; с `QT_QPA_PLATFORM=offscreen`
это проверка создания интерфейса без видимого окна.

Если модели лежат отдельно от установки Tesseract, задайте
`TESSDATA_PREFIX` — путь к каталогу с нужным `.traineddata`. Для проверки обоих языков
в этом каталоге должны лежать и `rus.traineddata`, и `eng.traineddata`:
Tesseract не добавляет к нему модели из стандартного каталога. Например, для локальной
проверки этой рабочей копии:

```sh
TESSDATA_PREFIX="$PWD/artifacts/tessdata" .venv/bin/python -m pytest -q
TESSDATA_PREFIX="$PWD/artifacts/tessdata" .venv/bin/python -m wow_fishing
```

Интеграционные OCR-тесты автоматически пропускаются, если нет Tesseract,
модели проверяемого языка или подходящего шрифта. Они читают сгенерированный русский
и английский текст, а также проверяют остановку на синтетических видео с сообщением
о полных сумках. Это отдельная проверка от оценки игровых кадров.

Replay исполняет тот же автомат состояний с виртуальным временем. Вместо ввода
используется `RecordingInput`; команды с временем и координатами попадают в JSON.
Автомат не может изменить существующее видео: ожидаемые забросы должны совпадать
с записанными. Лучше использовать полную запись бота от начала сеанса. Для
произвольного видео сравнивайте времена имитированных забросов с реальными;
рассинхронизированная запись не годится для оценки всего цикла.

## Данные и диагностика

Настройки: `%LOCALAPPDATA%\WoWFishing` на Windows,
`~/Library/Application Support/WoWFishing` на macOS.
Язык клиента сохраняется при запуске рыбалки или проверки записи; в старых настройках
без поля `game_language` используется русский. Во время сеанса менять язык нельзя.
Интерфейс приложения и сообщения состояния остаются на русском.
Последнее окно не сохраняется: при новом запуске его нужно выбрать снова.

В `sessions/<дата-время>/` сохраняется журнал `events.jsonl`. Образец поплавка
`bobber.png` записывается при завершении сеанса только при успешной калибровке.
При включённой записи и получении кадров добавляются `screen.avi`
(MJPEG, 20 кадров/с) и `frames.jsonl` с реальными временами кадров.
Replay автоматически подхватывает соседний `frames.jsonl`; его также можно
передать через `--timeline`. Сохраняйте видео и журнал времени вместе: без журнала
время вычисляется из номера кадра и FPS видео, что не учитывает задержки захвата.
В журнале каждая строка — JSON с полем `time` в секундах; времена должны строго
возрастать, а записей должно хватать на все обрабатываемые кадры.
Записи локальные, не отправляются по сети и не удаляются автоматически.
Каталоги `sessions/` и `reports/` находятся внутри указанного выше каталога
`WoWFishing`; GUI сохраняет каждый отчёт в `reports/<дата-время>.json`.
Счётчик «Попытки сбора» считает клики, а не подтверждённые предметы.

## Архитектура и проверка готовности

`engine.py` — автомат состояний без часов ОС, `vision.py` — поплавок и поклёвка,
`ocr.py` — очередь OCR с ограниченным числом ожидающих кадров, `safety.py` —
независимая остановка и защищённый ввод. `windows.py` изолирует платформенные API.
GUI и фоновые потоки связываются сигналами Qt; закрытие GUI дожидается потоков.
dxcam закреплён на 0.3.0: сопоставление мониторов использует внутренний список
DXGI outputs, изолированный в адаптере. При обновлении dxcam его нужно перепроверить.

Автотесты проверяют устойчивый и неоднозначный поиск, калибровку, волну и всплеск,
однократный клик, таймауты, задержанные/повторные результаты OCR, остановку и
координаты второго монитора. Тесты Win32 используют подмены API и не заменяют
настоящую проверку драйверов/игры.

В GitHub Actions настроены pytest и Ruff на Ubuntu и Windows с Python 3.12;
Qt запускается без видимого окна. Установка Tesseract и моделей в workflow
не предусмотрена, поэтому наличие CI не означает, что интеграционные OCR-тесты
выполнены. macOS проверяется локально.

На Windows предстоит проверить русский и английский клиенты, два одновременно
открытых окна, несколько мониторов и DPI 100/150%,
F8 во время OCR, переключение фокуса, закрытие выбранного клиента и полные сумки.
Цель приёмки: калибровка максимум за три заброса, минимум 18 успешных сборов из 20
в откалиброванном месте и остановка при сообщении о полных сумках до следующего
заброса. Кадры для настройки и оценки должны быть разными; эти показатели пока
не подтверждены. Пороги находятся в `Tuning` и `vision.py`.

API-ссылки: [DXcam](https://github.com/ra1nty/DXcam),
[pytesseract](https://github.com/madmaze/pytesseract),
[потоки и сигналы Qt](https://doc.qt.io/qtforpython-6/overviews/qtcore-threads-qobject.html).
